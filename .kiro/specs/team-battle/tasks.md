## Design note for steps 3 and 3b (2026-11-17, main line)

Measured in `index.html`: `player.` appears 192 times and `ai.` 113 times, 38 places already use `unitOf` / `unitsOf` / `activeSide`, `TeamBattle` is used in 3 places, and only 7 places compare a unit by identity (`u === player`, `opp === player`). `unitOf(side)`, `energyOf`, `itemOf`, `shieldOf` and `angleOf` return `unitsOf(side)[0]` and `TeamBattle.activeUnit` also returns the first unit.

Chosen approach (smallest change that keeps N = 1 byte-identical):
1. Keep one `activeIndex = { left: 0, right: 0 }` per side. `unitOf(side)`, `activeUnit()` and the five accessors above use `unitsOf(side)[activeIndex[side]]` instead of `[0]`.
2. `player` and `ai` stay as names but become thin live views of the ACTIVE unit of their side (a getter/setter forwarding object), so the 305 existing references act on the active unit without being rewritten. With N = 1 the active index is always 0 and the views forward to the same unit objects as today.
3. The 7 identity comparisons are rewritten to a side test (`sideOfUnit(u) === "left"`), because a forwarding view is not the same object as the unit.
4. Drawing, hit tests, status ticks and the win check iterate ALL units of a team (`unitsOf(side)`), not the two views.
5. Proof for every slice: `node scripts/record_match_transcript.mjs` must still match `docs/transcripts/n1_baseline.json` (sha256 `3d2b58eb...`, regenerated 2026-11-16 23:41) and the existing tests stay green, before any N = 2 behaviour is switched on by the `?team=2` flag.
