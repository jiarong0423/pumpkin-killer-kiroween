# Kiro task 104 — computer levels: three agent levels from three knobs, and a measured table (work block B05)

Owner request (2026-11-15): measure how strong a sub-agent is, then bring in computer levels from low to high. Target (owner decision): the middle level hits about 25 to 30 percent of its throws. Agents can sit on either team, so a level is a property of a seat, not of a side.

Read: `scripts/eval_agent_learning.py` (the baseline agent that learns only from `get_history`), `scripts/mcp_game_server.py` and `scripts/mcp_stdio_server.py` (the engine and the six tools), `docs/mcp_agent_protocol.md`, `docs/human_vs_ai_report.md` (what was measured before), `docs/kiro_75_mcp_plan_claude-sonnet-5.5.md`, `shared/constants.json`, `.kiro/specs/release-package/design.md` is NOT needed. Do not edit `index.html`, `scripts/mcp_*_server.py` or `scripts/eval_agent_learning.py`.

Create, saving after each:
1. `scripts/agent_levels.py` (stdlib only): three levels `easy`, `normal`, `hard`, each defined by the same three knobs and nothing else: (a) perception noise: how far the agent misreads the target position and the wind it is shown (applied by the agent to what `get_public_state` returns; the server is NOT changed); (b) aim error: random power error added to its chosen power; (c) memory: how many past throws from `get_history` it may use and whether it fits the wind term. Constants live in one table at the top of the file with a comment each. The agent logic is a wrapper around the learner in `eval_agent_learning.py` (import its functions; do not copy them). All randomness comes from a seed the caller passes; the same seed gives the same result.
2. `scripts/sweep_agent_levels.py`: for each level, run N seeded matches or rounds (default N = 200 throws per level over at least 5 seeds) through the MCP engine in `human_vs_agent` and `agent_vs_agent` modes, and print a table: level, throws, hits, hit rate, mean landing error in the first and second half of a match (learning curve), and 95 percent interval of the hit rate. Write the same table to `docs/ai_levels_sweep_20261115.md` (plain markdown) with the command and seeds used. Exit 1 if the levels are not ordered `easy < normal < hard` by hit rate.
3. `scripts/test_agent_levels.py` (`unittest`): same seed gives the same result; the three levels differ only by the knob table; hit rate order easy < normal < hard on a small fixed run; no level reads anything the server does not show publicly (assert it never calls anything outside the six tools); the table file is produced.
4. Tune ONLY the constants in the knob table until the middle level's hit rate is inside 25 to 30 percent over the sweep; report the final numbers honestly even if you cannot reach the target (say what you tried).

Run `python3 -B scripts/test_agent_levels.py` and `python3 -B scripts/sweep_agent_levels.py` and paste the last lines. If a shell call is refused, say so in the result file and do not invent output.
