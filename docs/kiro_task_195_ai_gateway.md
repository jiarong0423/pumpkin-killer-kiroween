Do, saving after each, running the tests after each:
1. `shared/ai_models.json`: `{"allowed": [<model id>...], "default": <model id>, "note": ...}` listing ONLY the cheapest tier of the Gemini API (the owner wants the lowest). You cannot verify current model names from here: set `"default"` to `null` and make the gateway REFUSE to start with a clear one-line error until the owner (or the main line after reading the official models page) fills it in; never guess a model id. The request may not choose a model: the gateway always uses `default`; `allowed` is only the ordered fallback list used when the default answers 404 or 429 (try the next entry once, then fail).
2. `scripts/pk_ai_gateway.py` (stdlib or the same dependencies as the relay; no new heavy dependency): `POST /ai` with `{prompt_kind, fields}` where `prompt_kind` is from a fixed allowlist of server-side templates (the browser sends data, never a free prompt; templates live in `shared/ai_prompts.json`). Owner 2026-11-16: "I will put two free keys, and when the quota runs out, switch to the computer opponent": the FIRST caller is the AI seat. Template `"aim"`: fields are only what the built-in AI may see (its own hero id and position, the enemy's position and hp, wind, weather, the fence hp, the round number; NEVER the enemy's private item slots or the human's pending choice) and the model must answer with a single JSON object `{"angle": <integer 25..80>, "power": <integer 15..100>}`; the gateway validates it (rejects anything else, clamps nothing: an invalid answer counts as `unavailable`). Keep a second tiny template `"taunt"` (at most 12 words) only as a test fixture for the template mechanism. Limits: 400 bytes body, 1 request per 3 s per client and 30 per hour per client (by remote address behind the proxy header the relay already trusts), a global daily cap from `PK_AI_DAILY_CAP` (default 200), output truncated to 160 characters and stripped of markup, a 6 s upstream timeout, and a visible fallback (the response says `{"ok": false, "reason": "unavailable"}` so the page can show a plain warning; never a silent substitute text). Log one line per call with codes only (status, model id, latency, key slot number), never the prompt text, the answer or any key.
3. Key rotation without redeploy and without pooling tricks: keys come from the environment variable `PK_GEMINI_KEYS` (comma separated, normally ONE key; two only while swapping an old key for a new one) and/or a file path in `PK_GEMINI_KEYS_FILE` re-read on every 60 seconds; the gateway uses slot 0 and moves to the next slot only on 401 or 403 for that slot (revoked or replaced key), with a 10 minute cool-down; on 429 it does NOT switch keys to dodge a quota: it waits for the limit and returns `unavailable` (using several free keys to get around a quota would break the provider's terms). Slot numbers are logged, key values never. A `/ai/health` returns only `{"configured": true|false, "slots": n, "model": "<default>"}`.
4. `deploy/nginx.conf`: proxy `location = /ai` and `/ai/health` to the gateway like `/relay` (same size limits). `deploy/entrypoint.sh`: start the gateway only when `PK_GEMINI_KEYS` or the file is set. `deploy/README_DEPLOY.md`: where to set the variables in Coolify (secret flag on), how to rotate (add the new key as second entry, restart, remove the old one), and what the owner must NOT do (commit a key, put it in `relay-config.js`, send it in a URL). `.env.example` with empty names only. Check `.gitignore` already ignores `.env` and `.env.*` (`!.env.example` allowed).
