# Kiro task 201 — a proper QR code system (join by scanning on a phone; a QR of the public site for the video and README)

Start after Kiro 200 (it owns `index.html` and `css/*.css`). Never push, never deploy, never read secret values, never commit. Frozen and pinned: everything in `docs/kiro_task_194_ui_and_multiplayer_orchestrated.md` plus the existing QR tests. Owner 2026-11-16: "make a QR code system".

What exists (read first): `js/qr_code.js` (offline encoder, byte mode, error-correction level L, versions 1 to 5, so at most 106 bytes: longer text throws `RangeError`), `scripts/test_qr_code.js`, `index.html` (`joinLink(code)`, `#room-details` with `#room-qr` 112 px, `#agent-room-qr`), `docs/relay_protocol_20261115.md`, `deploy/README_DEPLOY.md`.

Known weak points the main line found by reading the code: (a) the code is limited to 106 bytes, and a join link with a long hosted domain plus `?room=` and `&relay=` can exceed it, which makes the QR silently missing; (b) the on-screen QR is 112 CSS px, about 3 to 4 px per module at version 3 to 5, too small for a phone camera to read from a laptop or another phone across a table; (c) no test proves the picture decodes (the test compares the encoder with fixed vectors only); (d) there is no QR for the public site itself (video end card, README, Devpost image).

Do, saving after each, running the tests after each:
1. **Capacity**: extend the encoder to versions 1 to 10 at level L (and level M when the text fits version 7 or lower), choosing the smallest version that fits; keep the old vectors byte-identical for texts that fit version 5 at level L (existing tests stay green). Never throw into the page: if the text still does not fit, `QrCode.draw` returns `false` and the page shows the join link as large selectable text instead.
2. **Join link stays short**: `joinLink(code)` must produce `ORIGIN + "/?room=" + CODE` (no other parameters) whenever the page address has no `?relay=`; when a relay override is present it is carried, but test that the typical hosted link (a 30 character domain) fits version 3 at level M.
3. **Lobby UI**: the QR is drawn at the largest integer module size that fits a box of at least 220 CSS px (hard minimum 180 px on a 392 px high landscape phone) on a white quiet zone of 4 modules, with the room code in large letters beside it, a "Copy link" button (with a plain text fallback when the clipboard is blocked), and a one-line plain hint "Scan with your phone camera, or open the link" (new i18n keys, both languages, literal keys). It must not cover the countdown board or the dock and must fit the phone viewports measured by `scripts/measure_phone_layout.mjs` (add the lobby view to the measurement and keep 0 overlaps).
4. **Decode proof**: `scripts/test_qr_decode.py` renders the encoder's module matrix (export it from `js/qr_code.js` through a small `node` call) to a PNG at 6 px per module with a 4 module quiet zone and decodes it with an installed decoder (try `pyzbar` or `cv2.QRCodeDetector` from OpenCV; both may be present: check with `python3 -c "import cv2"`; do NOT install anything: if no decoder is importable, skip with a clear message and say so in the result). Assert the decoded text equals the input for at least 200 random texts of 10 to 120 bytes including non-ASCII, at levels L and M, versions 1 to 10.
5. **Site QR**: `scripts/make_site_qr.js` takes a URL argument and writes `(not published)` (vector, crisp at any size, black on white, 4 module quiet zone) and prints the version and level; add it to the README's "Play" section as a placeholder-free instruction (the hosted URL is not known yet: the script is run by the owner with the real address; the README says exactly that command). Do not commit a QR for an address that does not exist.
6. All existing tests green; if Chinese characters were added run `python3 -B scripts/build_fonts.py`, `python3 -B scripts/test_fonts.py`, `python3 -B scripts/make_sw_precache.py --apply`.
7. Result `(not published)`: what changed, the capacity table (version, level, bytes), the decode test result (count decoded or skipped and why), commands with last lines, and what the main line must check by scanning from a second phone.
