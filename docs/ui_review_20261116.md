# UI numerical review — 2026-11-16

## Method

`scripts/shoot_views.mjs` uses Chrome DevTools Protocol at 873x392, 915x412,
844x390, 932x430, 667x375 (DPR 2.5), and 1440x900 (DPR 1). It saves the
start, battle, result, and settings views under `(not published)` without
opening, decoding, or attaching the PNGs.

For each state it collects every visible DOM text node's computed CSS and
physical-device font sizes, focusable interactive rectangles, viewport and
overflow clipping, line boxes in buttons/chips, solid-background contrast,
focus order, named HUD geometry, and stage/margin coverage. It does not claim
to measure canvas-drawn text or contrast on gradients/translucent backgrounds.
The result panel is canvas-drawn, so the result capture can verify its canvas
and overlay geometry but not its internal text metrics.

The five phone sizes retain a 16:9 stage and cover 79.8%, 71.0%, 82.1%,
73.1%, and 100.0% of their viewports respectively. The corresponding unused
geometric margin is 20.2%, 29.0%, 17.9%, 26.9%, and 0.0%. Desktop stage
coverage is 85.1% with a 14.9% margin. No DOM button or chip produced more
than two actual text line boxes. No inspected text on a fully solid background
had contrast below 4.5:1. Gradient and alpha-composited backgrounds were
intentionally excluded from that contrast conclusion.

## Other measured facts

- At 873x392, 915x412, 844x390, and 667x375 the start-language button is
  71.3x37 CSS px. It is a touch control below 44px tall. It should be included
  with the P0 target fix if it remains available on the start screen.
- At 1440x900 the AI seat-level buttons measure 40x32 CSS px. They are not a
  no-hover failure in the desktop measurement, but should use the same 44px
  target when the relevant device media query applies.
- The overlay/container intersections in the raw measurement that pair a
  container with its own descendants are intentional nesting. They are not
  included as defects. The HUD-plate intersections above are separate measured
  pairs and are actionable.
- Existing `scripts/release/export_manifest.json` already excludes
  `(not published)`; no manifest edit was necessary.
