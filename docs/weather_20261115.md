# Weather map effects, 2026-11-15

`Weather.forRound(seed, round, sceneId)` is deterministic public state. One result
covers its `startsRound` and `endsRound`, so every device uses the same two-round weather.
All numbers below are **PROVISIONAL** named constants in `js/weather.js`.

| Weather | Map effect | Match effect |
|---|---|---|
| Clear | none | attack ×1, move ×1 |
| Rain | thin wind-slanted streaks | attack ×0.9 (wet ammunition) |
| Snow | slow swaying flakes | move ×0.5 (36 px dice step becomes 18 px) |
| Storm | heavy rain and sparse yellow-white lightning | attack ×0.9; wind magnitude gets +1.5, retaining its sign |
| Fog | two translucent drifting bands | view only |

Scene weights are `Weather.WEIGHTS`: graveyard favours clear/fog/rain; church rain/storm/fog;
school rain/fog/clear; bell tower storm/clear/snow; pumpkin field clear/fog/snow. Every
scene can draw rain and snow. The default clear probability is 40%; map weights deliberately
vary around it.

## Main-line wiring

1. Load `js/weather.js` and `js/weather_fx.js` after the existing pure modules. At round start add:
   ```js
   state.weather = Weather.forRound(state.seed, state.round, state.sceneId);
   weatherFx = WeatherFx.create({ w: W, h: H, id: state.weather.id, seed: state.seed + state.weather.startsRound, quality: reducedMotion ? 'low' : 'high' });
   ```
2. In the fixed-step update call `weatherFx.update(dt, state.wind)`. Draw `weatherFx.draw(ctx)`
   after the background/scene layer and before units and HUD, so fog and precipitation remain map effects.
3. Replace a resolved normal-hit damage `damage` with `Weather.applyAttack(state.weather, damage)`.
   Replace a requested dice distance `pixels` with `Weather.applyMove(state.weather, pixels)` before clamping movement.
4. HUD text: `Weather: ${state.weather.label} (until R${state.weather.endsRound})`.
   Storm wind application must add `(wind === 0 ? 0 : Math.sign(wind) * state.weather.windBonus)`; do not change its sign.
5. Add `weather: Weather.publicState(state.weather)` to MCP public state. Add
   `Weather.hashText(state.weather)` to the canonical round-hash text after `seed`; the id and end round are required hash inputs.

`WeatherFx` has at most 220 high-quality items or 60 low-quality items. Low quality has a
quarter of the field and no lightning. Lightning lasts at most 150 ms and its overlay alpha is 0.35.

## Balance check

Rain and storm reduce both sides' resolved hit damage equally, so neither side gains a directional
advantage. After wiring, run `node scripts/sim_balance.js` with each weather forced in equal
numbers of rounds. Compare red/white win rate and mean hits-to-kill against clear; any difference
beyond sampling noise indicates an ordering, rounding, or weather-application asymmetry.
